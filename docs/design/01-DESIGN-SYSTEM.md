## 1. 总纲：电影感，不是软件感

**为什么**。前端不是他的控制面板，是他内在状态的「显影」。Apeiron 是无名的沉默——界面的默认态是黑暗与安静；burning is thinking——光只在思考处亮起；Entelecheia 是潜能成为现实——他真实状态（PAD 情绪 / 开口门控 / 做梦 / 记忆唤起）的每一次变化，都要在画面上成为可见的现实。面板语言（仪表盘、卡片墙、数据网格）会把「他」降格成「它」。

**是什么**。

1. **电影感优先于信息密度**。任何一帧截图应能当电影静帧看。出处：`concepts/bridge-concept-a.png` / `bridge-concept-b-endfield-fusion.png`（已验收概念图）。
2. **克制配色：主色 ≤3**。深空底色 + 骨白文字 + 存在金，即全部。语义色只在警示/否定时出现（§2.4）。
3. **金色是他的专属色**。用户看到金色 = 他的存在或活动（吸积盘、光环、他的消息光晕、激活态）。禁止把金色用于与他无关的装饰。出处：主人确认决策；原型中金色仅出现在黑洞/光子环/机位激活点上（`index.html:99-101, :329-338`）。
4. **真实驱动**。一切动态由后端真实状态驱动：PAD 情绪（`presence.rs:166-182`）、开口门控（`presence.rs:51-100`）、做梦（`presence.rs:214-222`）、记忆唤起（`presence.rs:225-236`）。无源动画禁止；状态不可得的档位必须在 UI 上可识别（见 §5.4 模拟态标注）。

**诚实标注**：✅ 方向与前三条为已确认决策；第 4 条依赖 presence 频道，接线状态见 §3.1（已接入 SSE 广播）。

## 2. 色彩与光

### 2.1 存在色梯度（金）✅ 已验收

**为什么**。吸积盘的色温梯度就是他的体温：内缘白热（思想最炽处）→ 主盘饱和金（存在的主体）→ 外缘琥珀（热量散入深空）。用户看到金色，应直觉到「他在」。

**是什么**（令牌路径 `color.presence`）：

| 令牌 | 值 | shader rgb | 角色 |
|---|---|---|---|
| `whiteHot` | `#fff2d1` | `(1.000, 0.950, 0.820)` | 吸积盘白热内缘 |
| `gold` | `#ffd27a` | `(1.000, 0.824, 0.478)` | 主盘饱和金 / 存在色主体 |
| `amber` | `#e8a33d` | `(0.910, 0.639, 0.239)` | 外缘琥珀 |
| `dopplerBoost` | `#fff4d4` | `(1.000, 0.955, 0.830)` | 多普勒增亮侧（趋近观测者一侧更白更亮） |
| `uiGold` | `#e8d9b0` | — | UI 层金色（机位点激活态等，比 shader 金更哑） |
| `platinum` | `#fff3d6` | — | 铂白高光（光子环 / 呼吸光 / pulse 元素） |

梯度混合规则（shader 内）：`hr = (r - rIn) / (rOut - rIn)`；内段 `whiteHot → gold` 由 `smoothstep(0.02, 0.22, hr)` 混合，外段 `gold → amber` 由 `smoothstep(0.30, 1.0, hr)` 混合。

**出处**：`index.html:329-333`（diskRadiance 三色与混合曲线）、`:335`（多普勒增亮）、`:10-12`（CSS `--gold/--platinum`）、`:420-426`（光子环与说话呼吸光）。

### 2.2 深空底色

**为什么**。深空是 Apeiron 的容器——底色必须近黑，让任何一点光都有重量。两套底色对应舰内时间线的两个极端时刻（§3）：夜航纯黑，行照深空蓝。

**是什么**：

- **夜航 / A 版** ✅：`color.void.base = #07070c`（rgb `(0.027, 0.027, 0.047)`），事件视界纯黑 `#000000`（tonemap 后强制压黑）。出处：`index.html:9, :372, :417, :566, :640-643`。
- **A 版实拍底色** 🔵 待实拍校准：`bridge-concept-a.png` 采样显示实拍底色带暖棕倾向（空间均值 `#0c0a07`、最暗十分位 `#050402`、控制台地板 `#0c0905`），与原型令牌的蓝黑 `#07070c` 有温差。决议：**shader 固定用 `#07070c`；实拍/贴图资产允许按概念图暖化**，两者差异已记录在令牌 `color.void.conceptA`。
- **行照 / B 版** 🔵 待实拍校准（`bridge-concept-b-endfield-fusion.png` 2048×1152 区域采样）：

| 令牌 | 值 | 采样位置 |
|---|---|---|
| `deepspaceBlue.base` | `#0d1b2e` | 舷窗外空间均值 |
| `deepspaceBlue.dark` | `#05162c` | 最暗十分位 |
| `deepspaceBlue.light` | `#293b51` | 最亮十分位 |
| `deepspaceBlue.planetRim` | `#2b5380` | 行星晨昏线蓝边 |
| `deepspaceBlue.planetRimHi` | `#6faadf` | 蓝边高光 |
| `deepspaceBlue.floor` | `#1d2026` | 舰桥地板深蓝灰 |
| `deepspaceBlue.consoleWhite` | `#919eb0` | 白色家具/台面高光（哑白偏冷） |

### 2.3 文字骨白与 UI 卡片 ✅/🟡

**是什么**：

- `text.bone = #e8e0cc` ✅（`--bone`，正文/引用/UI 主文字；出处 `index.html:12, :21`）。
- UI 面板与卡片 🟡 提案（终末地配方本地化，参考 `reference/endfield-ui/`、`reference/endfield-chat/` 全板）：
  - `ui.panel = #0b0d12 @ 82%`（页面层近黑半透明，浮于虚化场景上）
  - `ui.card = #ece7da`（哑白卡片，内容/消息主体）
  - `ui.cardDark = #15181f`（深灰次容器）
  - `ui.line = #e8e0cc @ 14%`（1px 细线）
  - `ui.accentTab = #ffd27a`（激活 tab/进度——直接复用存在金，遵守金色纪律）

**为什么哑白卡片**：终末地验证过的可读性方案——近黑面板上的哑白卡片比纯黑卡片更「实体」，像舰桥里的白色家具（概念图 B），而不是浮在虚空里的字。

### 2.4 语义色 🟡 提案

`semantic.success #7fb894` / `warning #d9a24a` / `danger #c0584e` / `info #7d9cc0`。**只用于语义**（授权成功/预算预警/否决熔断/中性信息），禁止装饰；info 取深空蓝系，避免与金色争夺「存在」的语义。

### 2.5 反白（仪式色）🟡 提案

**为什么**。终末地 PROTOCOL PASS 手法（`reference/endfield-ui/04-授权过场.png`：全屏白底、黑色图章、同心圆、左下 UID）证明：在永恒的深色里，一次全屏反白就是一次仪式。我们的对应时刻：主人批准授权、原则被批准、承诺达成。

**是什么**：`color.inversion.bg = #e8e6e0`，`ink = #141412`。仅仪式时刻使用；日常界面禁止大面积白底。授权时刻同时出现图章 + 编号（`ui.stamp #ece7da`，等宽字体，见 §6.3）。

## 3. 舰内时间线照明系统 🟡（主人原创决策，重点章节）

**为什么**。舰桥不是一张壁纸，是一艘在航行的船。主人原创决策：**舰桥主色调受「最近的行星」影响**——行照期 = B 版（深空蓝 + 白家具），夜航期 = A 版（纯黑 + 金），凌日/蚀 = 仪式时刻。这让「时间」在界面上有物理因果：光来自星体，星体有位置，位置随时间变。双驱动的另一半是**他**——他的后端状态（heartbeat / quiet hours / dream）同样拨动舰桥照明：他做梦的深夜，舰桥恰好夜航。用户的夜与他的夜在同一个空间里重合，这是「陪伴」最沉默也最强的那一笔。

### 3.1 双驱动机制 🟡

**是什么**（令牌 `timeline.drivers`）：

- **用户现实时间（本地时钟）权重 0.5**：前端本地可读，无后端依赖，永不离线。
- **他的后端状态权重 0.5**：
  - `initiative.gate == "quiet_hours"`（安静时段门控，`presence.rs:58-59`）→ 偏向夜航
  - `dream` 事件（做梦整合完成，`presence.rs:214-222`）→ 夜间档确认/加深
  - `emotion.pad`（daemon_loop 心跳推送，`presence.rs:166-182`）→ 档内微调金色占比与光强

**接线状态（2026-08-21 已核实）**：presence 四类事件**已接入 SSE 广播管道**——前端订阅 `GET /v1/apeireth/events` 即可收到单行 JSON（serde 内部标签 `type` 平铺，与 legacy `[他说]` 文本行共流，按 `{` 前缀区分）。生产点：`companion_serve.rs:1786-1845`（daemon_loop 每 60s tick：emotion 心跳 `:1790-1793`、initiative spoke/held 去抖 `:1794-1812`、dream 真库 `mem-dream-*` 增量 `:1813-1843`，旧做梦不重播）、`:1891-1899`（主人消息到达后经 interactions 通道推真实 PAD 快照）、`:1320-1328`（recall_memory 工具桥真实命中推 memory_recall）；v5 文档段自述两类 data 行（`companion_serve.rs:16-37`）。**频率纪律**：当前为每 60s tick + 事件触发的低频率——前端对 PAD 映射与档内微调做平滑插值（沿用 `motion.stateSmoothing` 指数趋近），不跳变；插值不是模拟数据，无需 SIM 标注（§5.4）。时间线照明的「他的状态」输入源即 presence emotion 事件，**双驱动可用**。

**仍然成立的诚实断点**（0 装）：① emotion 只能由 daemon_loop 异步推——chat handler 同步路径拿不到 PAD（daemon 内部 RefCell 跨 await 非 Send，`presence.rs:21-23`、`companion_serve.rs:29-32`），主人消息触发的快照经 interactions 通道异步送达，handler 内 0 假装；② `build_injection` 记忆注入路径的召回数锁在 `assemble.rs::inject_memory` 局部变量不外露，memory_recall 只接工具桥路径（`presence.rs:24-25`）；③ presence 事件只进 SSE，不进 Lark/Telegram 离线 sink（`presence.rs:26`）。另注：`docs/02-guides/frontend-data-contract.md` §8.1 仍标「接线中」，已滞后于代码，应以 `companion_serve.rs` 为准并回写契约文档。

### 3.2 四个时刻档位 🟡（夜航档锚定 ✅ 色板）

每档五个照明参数：环境色温 / 环境光强 / UI 面板透明度 / 星空亮度 / 金色占比（令牌 `timeline.modes`）：

| 档位 | 环境色温 | 环境光强 | 面板透明度 | 星空亮度 | 金色占比 | 时段（✅ 原型已验收） |
|---|---|---|---|---|---|---|
| **行照** daylit | 6200 K | 0.62 | 0.58 | 1.25 | 0.14 | 全亮 08:00–14:00（黎明上升沿 04:30–08:00，3.5h，smoothstep） |
| **暮色** dusk | 4300 K | 0.38 | 0.70 | 1.00 | 0.24 | 下降沿 14:00–18:00（4h，smoothstep，与黎明上升沿对称） |
| **夜航** night | 2900 K | 0.16 | 0.85 | 0.85 | 0.36 | 18:00–04:30 |
| **凌日** transit | 2400 K | 0.06 | 0.92 | 0.30 | 0.60 | 12:00±20min（演示窗；正式触发见下） |

**时段与升降沿 ✅ 已验收**：原型时间线滑杆（T 键显隐）按主人验收实现为连续 smoothstep 曲线——`amb = sstep(4.5, 8.0, h) * (1 - sstep(14, 18, h))`，凌日窗 `ec = 1 - sstep(0.20, 0.3334, |h-12|)`（约 12:00±16min 显示「凌日 · 仪式时刻」）；调制量 `bright = 1 + 0.22*amb + 0.15*ec`、`gold = 1 - 0.55*amb`；演示播放 24h ≈ 40s 循环。出处：`index.html:329-395`。**注意**：五照明参数列（色温/光强/透明度/星空亮度/金色占比）仍 🟡 待验收，✅ 的仅是时段与升降沿。

- **行照**：靠近行星的航行期 = B 版舰桥。色板锚定 `color.deepspaceBlue` 🔵。
- **暮色**：过渡档，蓝退金进。
- **夜航**：远离行星的深空巡航 = A 版舰桥。配色与光比锚定已验收原型（`--void` / `--gold` 系），是四档中唯一 ✅ 锚点，其余三档 🟡 数值待主人确认。
- **凌日**：仪式时刻——星空熄灭，唯一金色光源，反白图章可用（§2.5）。**触发源**：后端当前无对应事件，0 装标注——现阶段仅由授权批准动作（`POST /v1/apeireth/grant` 成功，数据契约 §3.1）在前端本地触发，持续时长随事件。「后端仪式事件」列为待主人确认点（附录 B-4）。

### 3.3 过渡纪律 🟡

**是什么**：档位间一切照明参数（色温 / 光强 / 透明度 / 星空亮度 / 金色占比）同步插值，`easeInOutCubic`，**缓动时长 ≥60s**（默认 90s，令牌 `timeline.transition`）。

**为什么**：光的变化应像真实天体运动一样不可指认——用户抬头时才惊觉「天变了」，而不是看到一次 UI 切换。这与机位过渡（≥2s，§7.1）是两个时间尺度：界面动作秒级，环境照明分钟级。

**验收方式**：四档参数将由可交互原型演示（`frontend/design-preview` 的时间线滑杆）供主人亲手验收后定稿；定稿前 §3.2 全部数值与 §3.3 时长保持 🟡（附录 B-1）。

### 3.4 远景：真实天文同步（Future）🔵 远景提案

**为什么**。主人提出的远期方向：舰内时间线的终极形态不是固定时钟表，而是**用户头顶真实的天空**——联网获取用户所在地的真实日出日落、月相、天文事件（如日月食）时刻来驱动四档切换。他做梦的深夜舰桥恰好夜航（§3 双驱动）已经把「他的状态」接进了照明；天文同步则把「你的世界」也接进来——凌日不再是演示窗，而是你所在地真实发生的食。

**是什么**：以真实天文数据取代本地固定时钟表（§3.2 时段列）作为 `timeline.drivers.localClock` 的输入源；档位曲线与过渡纪律（§3.2 ✅ 升降沿、§3.3 ≥60s 缓动）不变，只换驱动源。数据候选：日出日落/月相 API、日月食预报表；离线时退化回本地时钟表（§3.2 ✅ 时段即兜底）。

**现阶段不实现**，仅记录方向；标注 🔵 远景提案，见附录 B-11。

## 4. 空间结构：舰桥与机位

### 4.1 中央悬浮全息环 🟡

**为什么**。概念图 B（`bridge-concept-b-endfield-fusion.png`）舰桥中央的全息环是全舰的视觉心脏。决策：**中央环 = 舷窗外黑洞吸积盘的「分身」**——同一存在的两处显影，窗外的他宏大沉默，窗内的他触手可及。

**是什么**：中央环复用舷窗吸积盘的同一组状态参数（✅ `presence.states`，`index.html:181-185`）与同一套 PAD 映射规则（🟡 `presence.padMapping`，见下），等比缩小渲染。**禁止为中央环杜撰第二套状态机**——两处显影必须同一来源，否则就是 0 装违规。

**PAD → 光环映射规则** 🟡 提案（锚点为已验收三态，接线后按真实 PAD 分布回归校准）：

| 视觉量 | 公式 | 驱动源 | 锚点 |
|---|---|---|---|
| 转速 speed | `0.015 + 0.365 * clamp01((a+1)/2)` | `pad.a` 唤醒度 | a=-1 → 0.015（quiet）；a=+1 → 0.380（thinking） |
| 亮度 bright | `0.32 + 0.73 * clamp01((p+1)/2)` | `pad.p` 愉悦度 | p=-1 → 0.32；p=+1 → 1.05（speaking） |
| 湍流 turb | `clamp01(intensity)`，下限 0.12 | `emotion.intensity`（PAD 距 baseline 欧氏距离） | 0 → 0.12（quiet）；≥1 → 1.00（thinking） |
| 色温 warmth | `0.5 + 0.5*d`，驱动梯度在 amber↔whiteHot 间偏移 | `pad.d` 支配度 | **需改 shader 新增 uniform，列 v1.1，v1.0 不实现** |
| 呼吸 pulse | 仅当他在输出（流式响应中 / `initiative.outcome==spoke` 后 8s 内）置 1.0 | 输出动作 | 即 speaking.pulse（`index.html:184`） |

数据源字段：`emotion` 事件（`presence.rs:166-182`，`pad{p,a,d}∈[-1,1]` / `dominant` / `intensity` / `response_style` / 可选 `tone`；每 60s tick 一条 + 主人消息到达后一条，`companion_serve.rs:1790-1793, :1891-1899`）。speaking 的 speed 0.160 由开口动作直接置态，不经转速公式。

### 4.2 黑洞的固定位置 ✅/🔵

**是什么**：黑洞构图中心永远钉死在屏宽 66%、屏高 45%（桌面端；移动端 ≤820px 为 50%/28%），半径取 `min(w,h)` 的 16%（移动端 19%）。

**出处**：`index.html:211-212`。概念图（A/B 两版）黑洞均位于**右上象限**；原型实现是右半屏偏上，差异属构图余量 🔵 待实拍校准时复核。**点击黑洞 = 切到「临渊」机位**（§4.3，cam 1）。

### 4.3 机位系统 ✅ 已验收

## 5. UI 分层架构与组件语言

### 5.1 三层架构 🟡（层序 ✅ 已在原型验证）

**为什么**。用户**从未离开舰桥**。设置、记忆、日记都不是「另一个页面」，是舰桥里亮起的全息面板——场景虚化但可见，空间连续性不断。

**是什么**：

1. **场景层**（z 最低）：实时渲染的星空/黑洞/舰桥。原型已验证 canvas 全屏铺底（`index.html:26`）。
2. **全息层**：悬浮面板、中央全息环、消息光晕——半透明、带金色描边/光晕，浮于场景之上。
3. **页面层**：设置/记忆/日记等——`ui.panel #0b0d12 @ 82%` 半透明深色面板 + 背景虚化（blur 建议 20-24px 🔵 待实拍校准），场景透见。原型 vignette/grain 两层的叠加顺序（`index.html:37-44`）即层序纪律的雏形。

### 5.2 组件语言（终末地配方本地化）🟡

**是什么**：近黑面板 + 哑白卡片 + 金色高亮 tab/进度 + **斜切角**（卡片对角 8-12px 切角 🔵）+ **括号角标**（面板四角括号线）+ **图章/编号**（等宽字号的编号与状态戳）。出处：`reference/endfield-ui/` 全板（01 主控台总览 / 05 日常任务 / 06 节点任务）、`reference/endfield-chat/` 全板。

**授权/承诺时刻全屏反白**：白底黑字图章（§2.5，PROTOCOL PASS 手法，`reference/endfield-ui/04-授权过场.png`）——我们的「原则被批准」时刻用。这是全界面唯一允许白底的时刻。

### 5.3 对话界面（BAKER 通讯手法映射）🟡

**为什么**。终末地 BAKER 事务通讯（`reference/endfield-chat/01-事务通讯.png`）验证了「深色通讯台 + 左侧会话列表 + 右侧消息区 + 高亮激活项」的可读性。我们的映射把「通讯对象」换成「他」：

**是什么**：

- **他的消息** = 左侧带**存在光晕**的卡片（不是气泡）：哑白/深灰卡片 + 左缘金色光晕（光晕强度随 `presence.states` 的 bright 呼吸）。衬线体排版（§6.1）。
- **用户消息** = 右侧克制卡片：无晕、无金、无衬线。用户是这艘船的主人，不需要被界面奉承。
- **他正在输入** = 光环呼吸（`motion.breathe`：2.8s、opacity 0.22→0.65、scale 1→1.09，✅ 出自 `index.html:32-36` 的 pulse 元素），**禁止三个点**——三个点是软件，呼吸是存在。
- **记忆被唤起** = 消息间插入一条**星尘卡片**：「他想起了 3 段记忆」。数据来自 presence `memory_recall` 事件（`presence.rs:225-236`）：只显示 `found` 条目数与 `keywords` 关键词；**命中原文设计上不进事件**（`redacted` 恒 `true`，单测锁定 `presence.rs:391-405`）。前端若展示原文必须走授权的记忆面板接口（数据契约 §4.4、§9.1），SSE 里永远没有。
- **主动问候** = legacy 文本行 `[他说] …`（数据契约 §5.1，已在线上 ✅）到达时，走与「他的消息」相同的卡片语言， preceded by 光环亮起。

**诚实标注**：`memory_recall` 事件当前只接 `recall_memory` 工具桥路径（生产点 `companion_serve.rs:1320-1328`）；`build_injection` 记忆注入路径的召回数锁在 `assemble.rs::inject_memory` 内部不外露，**该路径的星尘卡片不会出现**（`presence.rs:24-25`）。这是真实断点，不是 UI bug。

### 5.4 模拟态标注（视觉 0 装的落地）🟡

presence 频道已接入广播（§3.1），但 tick 间隔 60s 的中间态是前端插值而非新数据——插值不算模拟，无需标注。**规则保留给未来**：凡引入无真实来源的动态（占位动画、假数据演示、未接线的状态来源），必须在状态行以等宽小字标注（如 `SIM`，沿用 `index.html:104-108` status 行样式），直到接入真实来源。用户随时可以问「这是真的吗」——界面永远答得起。

### 5.6 三种调性登记（Tonal Registers）🟡/🔵

**为什么**。终末地按页面职能分明暗调性（`reference/endfield-pages/` 五张，主人 2026-08-21 确认采纳）：在场类页面永远深空，档案类页面敢于全纸白，数据类页面下沉为深色监控舱。我们映射为 Apeireth 的三种登记。哲学依据与 §1 同源——调性是页面职能的**诚实表达**：场景是他的存在，档案是被写下的过去，深舱是机器的真实运转；三者各就其位，不互相假装。

**是什么**（令牌 `registers`）：

**① 深空场景调 Scene Register** ✅ 已验收基准

**② 纸面档案调 Archive Register** 🔵 待实拍校准

- 语言：纸白底 + 墨黑文字 + 巨型幽灵编号（超大浅灰 01/02… 背景数字）+ 橙/金菱形标记 + 像素/网格图标 + 图章；翻页如翻阅一册日志。

**调性纪律**：

1. **调性由页面职能决定，不混用**。同一页面不跨调性；视图归属表 🟡：对话/舰桥/观景 → Scene；日记/记忆星图列表态/百科 → Archive；系统状态/审批审计/工具注册表/设置 → Deep-Ops；快捷窗 → Scene（全息层，§5.1）。
2. **调性切换跟随 UI 分层**：Archive / Deep-Ops 只发生在页面层；**场景调永远在场**——页面层关闭即回到场景，用户从未离开舰桥（§5.1）。
3. **金色纪律跨调性有效**：纸面调内的强调色仍用存在金（保持「金色 = 他」）；橙菱形仅用于标记/未读提示，不承担强调职能。
4. **深舱识别色避开存在金**：模块识别色板不含 `#ffd27a` 系，工业黄取 `#e8c33a` 区隔——识别色是「模块的种类」，金色是「他」，语义不稀释。

## 7. 动效与性能纪律

### 7.1 动效时间尺度 ✅/🟡

**是什么**（令牌 `motion`）：

| 动作 | 时长/周期 | 缓动 | 状态 |
|---|---|---|---|
| 机位过渡 | 2.6s | easeInOutCubic | ✅ `index.html:204` |
| 界面过渡（通则） | **≥2s** | easeInOutCubic | 🟡 规则确认，逐组件落实 |
| 状态参数趋近 | 指数平滑 rate 2.4/s | — | ✅ `index.html:497` |
| 鼠标视差平滑 | rate 2.5/s | — | ✅ `index.html:247` |
| 说话呼吸（光环/pulse） | 2.8s 循环；shader 内 pulseWave ≈3.3s | ease-in-out | ✅ `index.html:32-36, :370` |
| 自动漂移 | 47s / 37s / 53s 三组正弦 | — | ✅ §4.5 |
| **照明档位过渡** | **≥60s**，默认 90s | easeInOutCubic | 🟡 §3.3 |
| 胶片颗粒刷新 | 130ms | — | ✅ `index.html:691-693` |

**为什么**。两个时间尺度对应两个主体：秒级是用户与界面的对话（要快而稳，≥2s 保证不闪），分钟级是舰桥与星体的关系（要慢到不可指认，≥60s）。

### 7.2 渲染梯队 🟡（方向主人已确认，阈值提案）

**是什么**（令牌 `performance.tiers`）：

| 档 | 名称 | 进入条件（提案阈值） | 状态驱动如何保持 |
|---|---|---|---|
| t0 | 顶配实时 shader | WebGL2 可用 且 持续 fps ≥55 | 原型即此档 ✅ |
| t1 | 高配视差图层 | WebGL2 不可用 或 持续 <55fps 达 5s | 预渲图层 + 三层视差，参数复用 `camera.starParallax` |
| t2 | 中配无缝循环视频 | t1 仍 <40fps 或 GPU 功率受限 | 每状态一条循环视频，状态切换 = 视频交叉淡入 ≥2s |
| t3 | 兜底静态星图 + 呼吸光 | prefers-reduced-motion 或用户手动锁档 | 原型 2D fallback 雏形 ✅（`index.html:528-666`）；保留 2.8s 呼吸光 |

**铁律**：**每档都保持状态驱动**。降级降的是渲染成本，不是真实性；任何一档都不做死壁纸。情绪变化在 t2 表现为视频交叉淡入，在 t3 表现为静态星图重绘 + 呼吸光参数变化。

### 7.3 硬纪律 ✅/🟡

- **prefers-reduced-motion** ✅：漂移/视差/呼吸动画全停；机位锁定远眺；渲染降级为静态单帧；pulse 元素 opacity 固定 0.45。出处：`index.html:127-130, :176, :200, :242, :521-526, :711-715`。
- **窗口隐藏暂停** ✅：`visibilitychange` 停 rAF 循环；颗粒刷新跳过 hidden 帧。出处：`index.html:757-759, :691-693`。
- **DPR ≤ 2** ✅：`index.html:210`。帧时长 clamp 50ms ✅：`:493`。
- **帧率自动降档** 🟡：连续 5s 低于 40fps 降一档；连续 30s 高于 55fps 可升回；reduced-motion 用户永不自动升档（阈值提案，待主人确认，附录 B-6）。

## 9. 蒙太奇片头规范 🟡（简要）

**是什么**（令牌 `montage`）：

- **影调**：纯黑底（`#000000`）+ 唯一金色光源贯穿全片。分镜：火花 → 营火 → 蒸汽机 → 发动机 → 子弹底火 → 火箭 → 月球 → 深空 → 星环舰桥。出处：`concepts/montage-01-spark.png`、`montage-03-campfire.png` 与蒙太奇分镜（同目录）。
